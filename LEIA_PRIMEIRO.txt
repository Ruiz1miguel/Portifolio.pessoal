PORTFÓLIO DWS - HTML + CSS + JAVASCRIPT + PYTHON FLASK + MYSQL

1) O GitHub Pages hospeda apenas o FRONTEND. Ele NÃO executa Flask nem MySQL.
2) Importe backend/banco.sql em um MySQL local ou online.
3) Hospede backend/app.py em um servidor Python com acesso ao MySQL (ex.: serviço que suporte Flask).
   Diretório raiz do backend: backend/
   Instalação: pip install -r requirements.txt
   Comando de inicialização: gunicorn app:app
4) Configure as variáveis de ambiente do servidor conforme backend/.env.example.
   Não envie senhas do banco nem ADMIN_API_KEY para o GitHub ou para js/config.js.
5) Em js/config.js, substitua COLE_A_URL_DA_API_AQUI pela URL HTTPS real da API.
6) Configure ALLOWED_ORIGINS com a origem do seu github.io (ex.: https://usuario.github.io).
7) Publique a parte estática (index.html, css, js, pages, img) no GitHub Pages.
8) Abra pages/admin.html. A página abre diretamente, sem login de e-mail/senha.
   Ao fazer a primeira operação protegida, será solicitada a CHAVE ADMINISTRATIVA.
   A chave fica só na memória da aba, não é salva em arquivos nem localStorage.

TESTE LOCAL SEM CHAVE (SOMENTE NA PRÓPRIA MÁQUINA):
- Defina ADMIN_MODE=local, deixe ADMIN_API_KEY vazia, execute python app.py.
- Configure js/config.js com http://127.0.0.1:5000.
- Sirva o frontend via Live Server em http://localhost:5500.
- Não use ADMIN_MODE=local como substituto de segurança em produção.

CRUD E APOSTILAS:
- CREATE: POST /api/projetos -> INSERT INTO
- READ: GET /api/projetos -> SELECT
- UPDATE: PUT /api/projetos/id -> UPDATE
- DELETE: DELETE /api/projetos/id -> DELETE
- Contato: POST /api/mensagens -> INSERT INTO
- Painel: GET/DELETE /api/mensagens -> SELECT/DELETE
- HTML semântico, CSS responsivo, eventos DOM, Fetch, JSON, Git/GitHub e MySQL.
- A mudança em relação às apostilas é Python Flask no lugar de PHP.

ATENÇÃO: Sem uma API hospedada, um MySQL acessível e as variáveis configuradas,
o CRUD online não funcionará. O ZIP não faz a hospedagem automaticamente.
