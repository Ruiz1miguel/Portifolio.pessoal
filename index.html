PORTFOLIO PARA GITHUB PAGES + SUPABASE VOCE JA CRIOU as tabelas projetos, mensagens e admins no Supabase. NAO execute novamente o supabase.sql: as politicas ja existem. 1) Abra js/config.js. 2) Substitua COLE_A_PROJECT_URL_AQUI pela Project URL exata copiada do Supabase (Project Settings > Data API). 3) Substitua COLE_A_PUBLISHABLE_KEY_AQUI pela sua sb_publishable_... (Project Settings > API Keys). Nunca use sb_secret_ nem service_role. 4) Salve. No VS Code use Live Server para testar, ou publique no GitHub Pages. 5) No GitHub, crie um repositorio, envie O CONTEUDO DESTA PASTA para a raiz (index.html deve ficar na raiz). Settings > Pages > Deploy from a branch > main > /(root) > Save. Aguarde o link ser disponibilizado. 6) Abra SEU-LINK/pages/admin.html e entre com email/senha da conta criada em Authentication > Users. O cadastro de projetos alimenta a galeria. 7) A pagina pages/contato.html envia mensagens para o banco. Se aparecer 'Esta conta nao e administradora', confirme no SQL Editor: SELECT * FROM public.admins; A linha do UID da conta deve estar presente. Se a galeria estiver vazia, cadastre um projeto no painel admin. Se houver erro de rede ou de permissoes, verifique URL/chave, autenticacao e politicas RLS; nao desative RLS. O GitHub Pages hospeda somente o frontend. O banco e login rodam no Supabase. O CRUD de projetos tem criar, listar, editar e excluir. As mensagens podem ser enviadas, listadas e excluidas (nao editadas). Esta versao foi validada estaticamente; ainda precisa ser testada com as credenciais e banco reais do seu projeto.
